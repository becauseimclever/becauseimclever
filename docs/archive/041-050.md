### 046 - Owner-Controlled MCP Draft Tools
**Status:** Completed (confirmed 2026-10-31)
**Summary:** Added an optional, disabled-by-default HTTPS `/mcp` endpoint to the existing server with exactly five owner-directed tools for bounded post listing/reading and eligible draft CRUD. Published posts are read-only; publishing and scheduling remain human-admin operations.
**Key decisions:** Use a dedicated privately configured MCP-only bearer token, authenticated independently on every request with live configuration revocation, effective HTTPS and same-origin checks, and no cookie fallback. Keep the official SDK transport stateless; reject MCP bearer credentials on other routes. Narrow validated contracts reject hidden fields and preserve author, slug, image, and publication fields. Parameterized PostgreSQL writes atomically require Draft status, no schedule, and the expected `xmin`; client-enforced deletion approval is required, not claimed as server-verifiable consent. No schema changes, separate service, OAuth flow, or token UI.
**Verification:** Recorded zero-warning/error solution build, 41 MCP tests including six real PostgreSQL row-lock race tests, actual-host official-client draft creation/deletion, and 968 CI-selected tests passed. Dedicated disposable local PostgreSQL is required for concurrency tests; they are excluded from ordinary unit-test runs. No production deployment was performed. Tokens and bodies must remain private; backend HTTP must stay restricted to the trusted reverse proxy.

### 048 - Admin-Only Draft Visibility
**Status:** Completed (confirmed 2026-10-31)
**Summary:** Closed unauthenticated direct-URL exposure of unpublished posts and uploaded images. Draft, Scheduled, and Debug content now returns 404 unless the visitor is authenticated and satisfies the configured Admin policy. Published content remains public; full and paginated listings return only Published posts, including legacy reader responses.
**Key decisions:** Enforce visibility in the HTTP controller while preserving permissive service lookup for authorized previews. Check the parent post before retrieving images; apply no-store caching to all post API responses, replacing the previous 24-hour image cache. Guest writers, including authors, cannot preview unpublished posts through public URLs; existing management/editor and owner-controlled MCP permissions remain unchanged. This corrects the HTTP exposure left by feature 032 without rewriting its historical decisions.
**Verification:** Anonymous access was reproduced by failing HTTP tests before implementation. The affected-project build and all 80 focused visibility/public/admin controller tests passed, covering all statuses and anonymous/writer/admin identities, custom admin-group configuration, preview content/image bytes, listing filters, no-store headers, and Published-to-Draft transitions. Completed locally; production deployment and live incognito verification remain outstanding. Purge existing proxy/CDN image caches if present; new headers cannot revoke cached or downloaded copies.
